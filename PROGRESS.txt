WHAT THE SYSTEM DOES (one line)
  A camera watches a person; AI pose estimation (MediaPipe) tracks their
  limbs; frequency analysis detects sustained rhythmic jerking (convulsive
  seizures only); then it alarms, alerts family on Telegram, saves a clip,
  and logs the event on a dashboard for a doctor to review.
  We do NOT have a trained seizure classifier and never claim one.

PHASE 1 - DETECTOR  (done)
--------------------------------------------------------------------------
  [x] monitor/capture.py  - webcam / video file / RTSP / phone (IP Webcam)
                            with real timestamps, downscaled to 640 wide
  [x] monitor/pose.py     - MediaPipe pose, 10 tracked points
                            (shoulders, elbows, wrists, knees, ankles)
  [x] monitor/detector.py - core logic, pure code, testable without a camera:
        - resamples movement to a fixed 15 Hz (works at any camera fps)
        - normalises by shoulder width (distance from camera doesn't matter)
        - fills short gaps; resets if the body is lost for too long
        - 4 s sliding window + FFT per point: amplitude, band-power ratio
          (1.5-6 Hz), peak prominence
        - needs 2+ limbs rhythmic at once
        - event starts after 8 s of rhythm (3 s in --demo mode),
          ends after 5 s without rhythm
        - 0-1 confidence score (heuristic, NOT a probability)
  [x] main.py - live window: skeleton, state, per-limb numbers, fps
  [x] All thresholds in config.yaml


--------------------------------------------------------------------------
PHASE 2 - RECORDING + STORAGE  (done)
--------------------------------------------------------------------------
  [x] monitor/recorder.py - always keeps the last 30 s in memory (~20 MB)
        - clip = 30 s before detection ... 30 s after the event ends
        - skeleton overlay + date/time/camera banner
        - privacy: person pixelated by default (whole frame if person lost)
        - H.264 MP4 via ffmpeg, so it plays in browsers
  [x] monitor/storage.py - SQLite event log (data/events.db):
        id, start, end, duration, confidence, clip, camera,
        review label (unreviewed / real seizure / false alarm), note
        - row saved the moment an event starts (survives crashes)

PHASE 3 - ALERTS  (done)
